FocusLock V7.6.4

Observed state:
- Website classification works.
- Focus/Entertainment seconds stay frozen.

Root cause in V7.6.3 Hybrid:
- HandleBrowserContext returned AccountedSeconds = 0.
- Browser seconds were delegated to the desktop heartbeat.
- The user's desktop heartbeat has already been shown to be unreliable.

Fix:
- Restore V7.3 Extension activeElapsedMilliseconds.
- Restore V7.3 direct BrowserContext accounting.
- Focus website credits Focus seconds from real focused+visible browser elapsed.
- Entertainment website consumes allowance/wallet from the same elapsed time.
- Browser entertainment policy calls explicitly ignore desktop-agent heartbeat.
- Desktop Activity browser path returns early to prevent double counting.
- All modern Profile/Settings/Tray/Bubble/Schedule features remain.
- publish\Data is untouched.
