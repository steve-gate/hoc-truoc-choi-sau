FocusLock V7.6.7

Root cause fixed:
- V7.6.6 App could say "100% match" while Guard still rejected the same text.
- App and Service no longer implement challenge comparison separately.
- Both now call FocusLock.Shared.Utilities.SettingsChallengeComparer.

UX redesign:
- Removed the two-column "correct / typed" diff boxes.
- Added a single live colored comparison preview:
  green = correct typed character
  red = wrong/extra typed character
  gray = expected character not typed yet
- Input border turns green when fully matched and red when mismatched.
- Unlock button is enabled only at 100% match.
- Guard still performs the authoritative final check using the exact same shared comparer.

Unchanged:
- Browser Core
- NativeHost
- Profile/wallet
- publish\Data
