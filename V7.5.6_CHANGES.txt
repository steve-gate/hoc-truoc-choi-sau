FocusLock V7.5.6 - Native Browser Foreground Architecture

Root cause proven by web-diagnostic.txt:
- Browser Bridge healthy and rules matched correctly.
- Desktop agent heartbeat/foreground verification was the failing dependency.
- This made Focus website stay uncounted and Entertainment website stay uncharged.

Architecture change:
- FocusLock.NativeHost now directly calls Win32 GetForegroundWindow() in the user session.
- NativeHost verifies whether the real foreground process is chrome.exe/msedge.exe.
- NativeHost measures foreground elapsed time using Stopwatch.
- Extension timing/window.focused values are no longer trusted for accounting.
- Guard credits/debits browser time only from NativeHost-verified elapsed milliseconds.
- Browser accounting no longer depends on desktop-agent heartbeat.
- GuardTick does not overwrite an active, NativeHost-verified browser session just because the desktop heartbeat is stale.
- Desktop Activity path never double-counts browser time.
- NativeHost is deployed side-by-side into a new versioned folder to avoid locked-DLL problems.

publish\Data is untouched.
